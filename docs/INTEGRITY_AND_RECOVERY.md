# Контроль целостности и восстановление

## Что делает проверка

Команда `selfcheck` дополнительно вызывает read-only инвентаризацию:
- ключевых исходных модулей Brain;
- JSON-хранилища памяти, задач и состояния модулей;
- всех снимков памяти и их SHA-256 sidecar-манифестов.

Проверка возвращает статусы и SHA-256, но не выводит содержимое, значения памяти, секреты или абсолютные пути. Файлы конфигурации, способные содержать ключи и пароли (`.env`, `config.py` и подобные), не читаются и отмечаются как исключённые политикой.

## Обнаружение изменений

Для кода сравнение с доверенным эталоном возможно только если вызывающая сторона передала SHA-256 baseline. Без него файл проверяется на существование и читаемость, а статус baseline остаётся `NOT_CONFIGURED`. Нельзя считать автоматически вычисленный текущий хеш доверенным эталоном: baseline должен быть создан/проверен отдельно и храниться независимо от проверяемого файла.

Проверка JSON-хранилищ проверяет структуру и уникальность идентификаторов. Проверка резервных копий повторно сверяет каждый снимок с sidecar SHA-256 и схемой. SHA-256 sidecar обнаруживает случайное повреждение, но сам по себе не защищает от злоумышленника, который одновременно заменил файл и манифест.

## Аварийное восстановление: текущая граница

- Память: доступна проверка снимка и атомарное восстановление через `memory.backup_restore.restore_snapshot`; перед восстановлением валидная текущая память сохраняется в отдельный снимок.
- Задачи: есть атомарные записи и восстановление незавершённых задач после перезапуска; отдельный проверенный backup/restore для истории задач ещё не реализован.
- Состояние модулей: есть проверка схемы и безопасное поведение при повреждении; согласованный backup/restore всех модульных данных ещё не реализован.
- Конфигурация и секреты: автоматическое восстановление запрещено; их резервирование требует отдельного зашифрованного экспорта и управления ключами.

## Правило безопасного восстановления

Инвентаризация ничего не исправляет автоматически. При статусе `FAIL` сначала сохраняется диагностический отчёт без приватного содержимого, затем выбирается конкретный проверенный снимок, проверяется его схема/хеш и только после явного подтверждения выполняется восстановление. Никогда не перезаписывать более новые пользовательские данные автоматически.

## Ограничения

- Без внешнего доверенного baseline проверка кода не может доказать, что файл не был изменён.
- Без HMAC/подписи и независимого хранения manifest не является защитой от целевой подмены.
- Нет согласованного снимка памяти + задач + конфигурации; это следующий этап 7.5.
- Проверка на POCO F6/Termux обязательна после прохождения CI.
