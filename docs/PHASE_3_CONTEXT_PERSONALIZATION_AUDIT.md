## Проверенные компоненты

- `project_context.py`: шесть доменов и нормализация RU/EN алиасов.
- `chat_system.py`: `context_domain` хранится в чате и индексе; старые чаты без поля трактуются как `general`.
- `chat_recall.py`: лексический поиск по сохранённым чатам, фильтр домена, исключение system/transient сообщений.
- `memory/memory_core.py`: Core profile + динамические факты, отбор по запросу, ограничение размера отдельных фактов и небольшой fresh fallback.
- `context_manager.py`: бюджет API/LOCAL, приоритет system/tool/recent history и сокращение сообщений.
- `task_manager.py`: JSON store, атомарная запись, checkpoint/plan, recovery активных задач.
- `brain.py`: recovery вызывается при старте; текущая память загружается через `get_relevant_memory`; Context Manager вызывается перед отправкой модели.

## Ограничения и риски

1. Проектные домены пока применяются к чатам, но не ко всем записям долговременной памяти. Нельзя автоматически выводить проектную принадлежность старых записей без явного решения и безопасной миграции.
2. Долгосрочные цели не отделены от обычных фактов/предпочтений типизированной схемой.
3. Recall истории — лексический, а не семантический; он формирует кандидатов контекста, а не гарантирует истинность или актуальность.
4. Восстановление незавершённой задачи сохраняет checkpoint, но требует явного выбора задачи пользователем; автоматическое возобновление внешних действий небезопасно.
5. Эта ветка не читает и не меняет пользовательский файл памяти, чаты или tasks.json в среде POCO F6.

## Границы реализации этой ветки

- Подключить уже существующий domain-aware chat recall к основному пути запроса.
- Ограничить объём извлекаемой истории.
- Fail closed при неизвестном домене или ошибке чтения истории.
- Сохранить read-only поведение и текущую схему пользовательских данных.
- Не запускать и не выполнять задачи автоматически.
- Не менять `brain_memory.json`, chat files, tasks store, local model servers или настройки устройства.

## Следующие отдельные решения

- Спроектировать явную привязку новых memory records к домену, определить глобальные категории и стратегию для legacy-записей.
- Спроектировать типизированные долгосрочные цели: владелец, статус, приоритет, горизонт, связанные проекты, дата пересмотра, источник и история изменений.
- Определить UX восстановления: какие задачи показывать, как сопоставлять задачу домену, и когда включать checkpoint в контекст без повторного исполнения.
