# Политика классификации и защиты данных

## Классы данных

| Класс | Примеры | Передача внешнему провайдеру |
|---|---|---|
| PUBLIC | Явно публичные справочные материалы и публикационные данные без секретов | Допустима при обычном выборе внешнего маршрута |
| INTERNAL | Системные правила, технические метаданные, результаты внутренних инструментов | Только в объёме, необходимом для запроса; проверять каждый новый источник |
| PERSONAL | Личная память, история прошлых чатов, пользовательские навыки/профили | Только LOCAL; внешняя маршрутизация удаляет эти блоки |
| SECRET | API-ключи, токены, пароли, приватные ключи и распознаваемые credential-паттерны | Запрещена; внешний вызов блокируется |
| USER_INPUT | Текущий текст пользователя | Пользователь сам выбирает провайдера; если обнаружен распознаваемый секрет, внешний вызов блокируется |

## Применение

- `privacy_policy.py` содержит классификатор сообщений, ограниченный сканер credential-паттернов и redaction helper.
- `context_manager.enforce_private_context_boundary()` применяет классификацию на последней границе перед внешней моделью.
- `brain.controller_execute()` блокирует внешний запрос, если в сообщениях обнаружен credential-паттерн.
- Публичная CPA-публикация отклоняет контент с распознаваемыми секретами; ошибки Telegram больше не возвращают URL с bot token.
- Конфигурационные файлы и переменные окружения этим модулем не читаются.

## Ограничения

- Сканер обнаруживает распространённые форматы ключей/токенов, но не может доказать отсутствие всех возможных секретов. Не отправляйте секреты в запросы.
- Обычный пользовательский текст не блокируется сам по себе: выбор внешнего провайдера остаётся явным действием пользователя.
- Если сканер достигает лимита объёма или глубины, он действует fail-closed.
- Защита не отменяет необходимость хранить секреты вне Git, не включать их в публичные публикации и не пересылать их вручную.
- Новые источники контекста и интеграции должны получать классификацию до подключения к внешней маршрутизации.

## Тесты

`test_privacy_policy.py` проверяет классификацию, фильтрацию, secret detection, redaction и fail-closed ограничения. `test_cpa_privacy.py` проверяет запрет публикации секретоподобного содержимого и отсутствие Telegram bot token в ошибках.
