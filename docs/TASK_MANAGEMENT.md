# Управление задачами

## Приоритеты

У каждой новой задачи есть приоритет:
- `critical` — критический;
- `high` — высокий;
- `normal` — обычный (значение по умолчанию);
- `low` — низкий.

Команда:

```text
задача приоритет <ID> <low|normal|high|critical>
```

Список `задачи` сортируется по приоритету: critical → high → normal → low. Внутри уровня используется время последнего обновления.

Старые записи без поля `priority` читаются как `normal`; чтение не переписывает хранилище. Неизвестный приоритет считается повреждением записи и не исправляется автоматически. Завершённой задаче нельзя менять приоритет.

## Остановка и продолжение

- `задача прервать <ID>` переводит активную задачу в состояние interrupted и сохраняет checkpoint/plan.
- `задача продолжить <ID>` — явное действие пользователя для повторного запуска.
- Прерванные шаги с неопределённым внешним эффектом не запускаются автоматически: сначала требуется ручная сверка.

Изменение приоритета не запускает и не останавливает выполнение. Вызовы инструментов и их разрешения продолжают проходить через существующие политики автономности и подтверждения.
